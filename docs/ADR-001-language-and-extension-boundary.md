# ADR-001：语言与扩展边界

| 项目 | 内容 |
|---|---|
| 状态 | 拟议，验证中 |
| 日期 | 2026-08-22 |
| 决策范围 | 服务端语言、公共契约、SDK 与外部扩展边界 |

## 1. 背景

ContentX 当前由 Go 服务端、Vue/TypeScript 管理后台和 TypeScript SDK 组成。Go 可以提供清晰的部署与运维路径，但编程语言也会影响贡献者数量、招聘、插件生态、二次开发成本和未来架构选择。

因此，Go 不能仅因为是当前实现就被视为永久产品承诺或唯一差异化。产品价值应来自自托管的数据边界，以及人和 AI Agent 共用时可授权、可审批、可追踪、可回滚的内容治理。

当前 `internal/plugin` 的 Go `Plugin` 接口只适合内置插件。Go `.so` 受 Go 版本、依赖、操作系统和构建链约束，不适合作为对外公共插件 ABI。

## 2. 候选方案

| 方案 | 收益 | 主要代价与风险 |
|---|---|---|
| 全部保留为 Go，并只支持 Go 插件 | 实现集中、调试直接 | 扩展作者必须使用 Go；跨版本与跨平台插件分发困难 |
| Go 核心 + 语言中立契约与进程外扩展 | 保留当前投资；应用和扩展不绑定 Go | 需要稳定的 API、事件、鉴权、超时和审计协议 |
| Go 控制平面 + 其他语言的独立服务 | 可按能力选择生态 | 部署、事务、追踪和故障处理复杂度上升 |
| 重写服务端 | 可重新选择生态 | 迁移成本最高；会重新引入已经解决的安全和数据问题，且目前缺少用户证据 |

## 3. 暂定决策

在取得用户和工程证据前，不启动整库重写。下一阶段采用“**Go 核心 + 语言中立公共契约**”作为可逆基线：

- Go 是当前服务端实现与运维选择，不是客户端、SDK 或扩展作者必须使用的语言。
- REST/OpenAPI、MCP 工具 schema 和版本化事件是公共契约；不得把 GORM 模型或内部 Go interface 当成外部 ABI。
- SDK 采用“契约生成核心 + 轻薄惯用封装”；TypeScript SDK 是第一个消费者，不是唯一 SDK。
- 异步集成优先使用 Webhook/事件协议；需要同步调用时采用进程外 HTTP/RPC，并统一身份、租户、超时、限流和审计。
- 可信本地扩展可评估带能力限制的 WASM；在验证前不承诺动态插件平台。
- 替换局部内部实现时，公共契约测试应保持不变。

这是一项待验证的架构决策，不代表 Go 永久不变，也不代表已经决定迁移。

## 4. 下一验证批次

1. 定义并实现默认关闭、published-only 的动态内容公开 REST 契约。
2. 用非 Go 客户端完成“读取内容类型 → 读取公开条目 → 处理分页与错误”的消费者冒烟测试。
3. 固定错误、分页、幂等、租户和身份语义，保证 SDK 不依赖内部 Go 类型。
4. 为进程外事件消费者或 WASM 做一个最小 spike，验证授权、超时、失败隔离和审计。
5. 收集部署体积、启动、维护成本、外部贡献和真实用户反馈，再决定保留 Go、采用混合架构或迁移局部能力。

## 5. 退出条件

- 一个非 Go 客户端无需理解 Go 类型即可完成完整的内容消费流程。
- OpenAPI、MCP 和事件契约具有版本与兼容规则。
- 当前 Go `Plugin` 接口被明确限定为内置适配层，不作为外部插件 ABI。
- 一个进程外扩展或 WASM spike 能被授权、限时、隔离并审计。
- 保留 Go、混合架构或迁移的下一决策有用户采用和维护成本证据，而不是仅依据语言偏好。
