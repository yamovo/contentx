# ContentX 产品需求

本文档定义 ContentX 的产品定位、承诺范围、非目标和版本验收标准。当前实现状态见[项目状态](./STATUS.md)，未完成计划见[路线图](./ROADMAP.md)。

## 1. 产品定位

ContentX 面向需要自托管内容平台的开发团队，提供统一的内容模型、发布工作流和多协议接口。系统优先保证：

- 数据与权限边界清晰
- 部署、升级、备份和恢复可重复
- API 契约稳定且可验证
- 管理后台适合内容团队日常使用
- AI Agent 只能在显式授权范围内读写内容

## 2. 目标用户

| 用户 | 主要需求 |
|---|---|
| 管理员 | 管理用户、角色、系统配置、备份和全部内容 |
| 编辑 | 审核、跨作者编辑、发布、定时和归档内容 |
| 作者 | 创建、编辑本人内容并提交审核 |
| API 客户端 | 按 API Token 权限读取或修改内容 |
| AI Agent | 通过 MCP 使用受控的查询、创建、更新和发布工具 |
| 运维人员 | 部署、监控、迁移、备份、恢复和排查服务 |

## 3. 功能范围

### 3.1 内容与工作流

- 文章、页面、分类、标签、评论和媒体
- 自定义内容类型、动态内容条目和国际化字段
- 草稿、待审核、定时、已发布和已归档状态
- 修订历史、版本恢复和文章更新乐观锁
- 内置全文检索、RSS、SEO、导航菜单和重定向

### 3.2 身份与安全

- JWT 访问令牌、刷新令牌轮换与吊销
- API Token、TOTP 和基于角色的权限控制
- 登录、注册和接口限流
- 认证失败、权限拒绝和关键业务操作审计
- 敏感审计字段统一脱敏

### 3.3 接口与自动化

- REST API 作为主要读写接口
- GraphQL 作为公开只读查询接口
- OpenAPI/Swagger 作为 REST 接口契约
- stdio 与 Streamable HTTP MCP
- Webhook 持久化队列、HMAC、目标地址防护、重试和并发限制

### 3.4 数据与存储

- SQLite、PostgreSQL 和 MySQL
- Redis 缓存、令牌吊销和登录保护；不可用时按能力降级
- 本地文件和 S3 兼容对象存储
- 数据库迁移、种子数据、备份和灾难恢复

### 3.5 管理后台

- Vue 3、TypeScript、Vite 和 Element Plus
- 基于 Vue Query 的服务器状态管理
- 按权限控制菜单、路由和操作
- 内容列表、编辑器、媒体库、用户角色、设置、Webhook、备份和审计页面

### 3.6 可观测性与部署

- 健康检查、结构化日志和请求 ID
- Prometheus 指标与 OpenTelemetry 追踪
- Docker Compose 生产基础部署
- Go、前端单测、浏览器 E2E、静态检查和 OpenAPI 漂移检查

## 4. 非目标

当前版本不承诺：

- GraphQL 写入或与 REST 完全等价的 GraphQL 能力
- 任意第三方插件的运行时加载与强隔离
- 完整数字资产管理、图片流水线或 CDN 控制面
- 企业级多租户、计费、SSO/OIDC、SLA 或合规认证
- Meilisearch 的正式生产集成
- 所有 S3 供应商的官方认证；当前仅完成 MinIO 真机兼容验证
- 完整多语言管理后台

非目标不得以不可用菜单、占位按钮或硬编码演示数据伪装为已交付功能。

## 5. 产品约束

- 普通文章更新不得绕过专用发布工作流。
- Author、Editor、Admin 的所有允许与拒绝路径必须在服务层或路由层复核。
- 公开接口不得返回草稿、私有或受密码保护内容。
- 审计日志不得记录密码、Token、密钥或 Webhook URL 查询凭据。
- 外部依赖能力必须具有超时、错误处理和可验证的降级路径。
- 仪表盘和分析页面只能展示真实数据；缺少数据时明确显示空状态。

## 6. 版本验收标准

一个版本只有在以下条件全部满足时才可发布：

1. `make check` 通过。
2. 浏览器关键流程 E2E 通过。
3. 新功能包含成功、失败和权限拒绝测试。
4. 数据库变更完成迁移验证；涉及恢复时在隔离环境完成恢复演练。
5. REST 变更重新生成 OpenAPI，且生成结果无漂移。
6. 外部服务能力至少使用一种真实兼容服务完成集成验证。
7. README、STATUS、ROADMAP、SOP 和 CHANGELOG 与实现同步。
8. 未完成能力明确记录在 STATUS 或 ROADMAP，不写入已交付清单。
9. 密钥、调试配置、测试数据和临时产物未进入版本库。

## 7. 后续方向

下一阶段优先建设多租户数据隔离、配额和用量计量。计费、SSO、媒体处理、完整 GraphQL、外部插件机制和 SDK 在多租户基础稳定后重新评估。具体顺序与退出条件见[路线图](./ROADMAP.md)。
