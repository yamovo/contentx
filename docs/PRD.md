# ContentX 产品需求

本文档定义 ContentX 的产品承诺范围、非目标和版本验收标准。统一的对外定位与选型口径见[产品定位](./POSITIONING.md)，当前实现状态见[项目状态](./STATUS.md)，未完成计划见[路线图](./ROADMAP.md)。

## 1. 产品定位

**ContentX：面向开发者和 AI Agent 的自托管 Headless CMS。**

ContentX 面向希望掌握部署与数据边界的开发团队，提供统一的内容模型、发布工作流，以及面向应用和 AI Agent 的多协议接口。当前服务端以 Go 构建，但公共 API、SDK 和外部扩展不要求采用 Go。内容编辑者通过管理后台参与日常生产，但产品的接入与扩展首先服务开发者和 Agent 构建者。

ContentX 的产品选择是：

- 自托管与数据控制是产品承诺；Go 是当前实现选择，其收益和生态约束通过 ADR 与实际采用持续验证
- 把 REST、OpenAPI、只读 GraphQL 和 MCP 作为清晰、可验证的接入边界
- 服务内部实现允许演进，公共 API、MCP、事件和 SDK 契约必须保持语言中立与版本兼容
- 把 AI Agent 视为受身份、权限、工作流和审计约束的客户端，而不是绕过治理的自动化入口
- 先保证内容正确性、安全性、可恢复性和可运维性，再扩展功能广度
- 不以插件数量与成熟平台正面竞赛，优先强化自托管、Agent 治理、语言中立契约和多租户隔离

系统优先保证：

- 数据与权限边界清晰
- 部署、升级、备份和恢复可重复
- API 契约稳定且可验证
- 管理后台适合内容团队日常使用
- AI Agent 只能在显式授权范围内读写内容

## 2. 目标用户

| 用户 | 主要需求 |
|---|---|
| 管理员 | 管理用户、角色、系统配置、备份和全部内容 |
| 编辑 | 审核、跨作者编辑、发布、定时和归档内容 |
| 作者 | 创建、编辑本人内容并提交审核 |
| API 客户端 | 按 API Token 权限读取或修改内容 |
| AI Agent | 通过 MCP 使用受控的查询、创建、更新和发布工具 |
| 运维人员 | 部署、监控、迁移、备份、恢复和排查服务 |

## 3. 功能范围

### 3.1 内容与工作流

- 文章、页面、分类、标签、评论和媒体
- 自定义内容类型、动态内容条目和国际化字段
- 草稿、待审核、定时、已发布和已归档状态
- 修订历史、版本恢复和文章更新乐观锁
- 内置全文检索、RSS、SEO、导航菜单和重定向

### 3.2 身份与安全

- JWT 访问令牌、刷新令牌轮换与吊销
- API Token、TOTP 和基于角色的权限控制
- 登录、注册和接口限流
- 认证失败、权限拒绝和关键业务操作审计
- 敏感审计字段统一脱敏

### 3.3 接口与自动化

- REST API 作为主要读写接口
- GraphQL 作为公开只读查询接口
- OpenAPI/Swagger 作为 REST 接口契约
- stdio 与 Streamable HTTP MCP
- Webhook 持久化队列、HMAC、目标地址防护、重试和并发限制

### 3.4 数据与存储

- SQLite、PostgreSQL 和 MySQL
- Redis 缓存、令牌吊销和登录保护；不可用时按能力降级
- 本地文件和 S3 兼容对象存储
- 数据库迁移、种子数据、备份和灾难恢复

### 3.5 管理后台

- Vue 3、TypeScript、Vite 和 Element Plus
- 基于 Vue Query 的服务器状态管理
- 按权限控制菜单、路由和操作
- 内容列表、编辑器、媒体库、用户角色、设置、Webhook、备份和审计页面

### 3.6 可观测性与部署

- 健康检查、结构化日志和请求 ID
- Prometheus 指标与 OpenTelemetry 追踪
- Docker Compose 生产基础部署
- Go、前端单测、浏览器 E2E、静态检查和 OpenAPI 漂移检查

## 4. 非目标

当前版本不承诺：

- GraphQL 写入或与 REST 完全等价的 GraphQL 能力
- 任意第三方插件的运行时加载与强隔离
- 完整数字资产管理、图片流水线或 CDN 控制面
- 计费、SSO/OIDC、SLA 或合规认证
- Meilisearch 的正式生产集成
- 所有 S3 供应商的官方认证；当前仅完成 MinIO 真机兼容验证
- 完整多语言管理后台

非目标不得以不可用菜单、占位按钮或硬编码演示数据伪装为已交付功能。

## 5. 产品约束

- 普通文章更新不得绕过专用发布工作流。
- Author、Editor、Admin 的所有允许与拒绝路径必须在服务层或路由层复核。
- 公开接口不得返回草稿、私有或受密码保护内容。
- 审计日志不得记录密码、Token、密钥或 Webhook URL 查询凭据。
- 外部依赖能力必须具有超时、错误处理和可验证的降级路径。
- 仪表盘和分析页面只能展示真实数据；缺少数据时明确显示空状态。
- 动态内容的创建、更新、导入和翻译不得绕过独立发布权限；公开交付只能读取显式开放且已发布的内容。
- 公共契约不得暴露 GORM 模型、内部 Go interface 或要求消费者理解 Go 类型。

## 6. 版本验收标准

一个版本只有在以下条件全部满足时才可发布：

1. `make check` 通过。
2. 浏览器关键流程 E2E 通过。
3. 新功能包含成功、失败和权限拒绝测试。
4. 数据库变更完成迁移验证；涉及恢复时在隔离环境完成恢复演练。
5. REST 变更重新生成 OpenAPI，且生成结果无漂移。
6. 外部服务能力至少使用一种真实兼容服务完成集成验证。
7. README、STATUS、ROADMAP、SOP 和 CHANGELOG 与实现同步。
8. 未完成能力明确记录在 STATUS 或 ROADMAP，不写入已交付清单。
9. 密钥、调试配置、测试数据和临时产物未进入版本库。

当前先完成语言与扩展边界决策、动态内容公开交付契约和发布权限收口，同时继续关闭多租户、RAG、Release 与 SDK 的既有生产阻断项。完整阶段顺序和退出条件见[路线图](./ROADMAP.md)，暂定技术决策见 [ADR-001](./ADR-001-language-and-extension-boundary.md)。
