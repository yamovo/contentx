# 产品需求

本文档定义 ContentX 的产品目标、功能范围和验收标准。当前进度见[项目状态](./STATUS.md)，计划见[路线图](./ROADMAP.md)。

## 产品定位

ContentX 面向需要自托管内容平台的开发团队，提供统一的内容模型、发布工作流和 API。系统优先保证部署简单、接口稳定、权限边界清晰，并通过 MCP 支持 AI Agent 在受控权限下读取和编辑内容。

## 目标

- 通过 REST、GraphQL 和 MCP 向多个客户端提供内容
- 支持从草稿到发布的完整内容生命周期
- 支持自定义内容类型、国际化和媒体资产
- 提供可审计的身份认证、授权和操作记录
- 支持单机开发以及 PostgreSQL、Redis 组成的生产部署
- 提供可重复执行的测试、备份、恢复和监控流程

## 非目标

当前版本不承诺以下能力：

- 完整的 GraphQL 写入接口
- 任意第三方插件的运行时加载与隔离
- 完整的图片处理、CDN 和数字资产管理
- 企业级多租户、计费、SSO 或合规认证
- Meilisearch 和 S3 兼容实现达到所有供应商的生产兼容性

## 用户角色

| 角色 | 主要职责 |
|---|---|
| 管理员 | 管理用户、角色、系统配置和全部内容 |
| 编辑 | 审核、编辑和发布内容 |
| 作者 | 创建并维护本人内容 |
| API 客户端 | 按 API Token 权限访问接口 |
| AI Agent | 通过 MCP 在显式授权范围内读取或修改内容 |

## 功能范围

### 内容管理

- 文章、页面、分类、标签和评论
- 自定义内容类型与内容条目
- 草稿、待审核、定时、已发布和已归档状态
- 修订历史、恢复、定时发布和国际化
- 内置全文检索与 RSS

### 媒体

- 上传、查询、更新和删除媒体
- 文件类型和大小限制
- 本地存储与 S3 兼容存储配置

### 接口

- REST API 作为主要读写接口
- GraphQL 作为公开只读查询接口
- OpenAPI/Swagger 作为 REST 接口规范
- MCP 提供只读工具以及受权限控制的创建、更新和发布工具

### 身份与安全

- JWT 访问令牌和刷新令牌
- API Token、TOTP 和基于角色的访问控制
- 登录与接口限流
- Webhook HMAC 签名、目标地址校验和重试
- 发布与普通编辑分离授权

### 运维

- SQLite、PostgreSQL 和 MySQL
- Redis 缓存及进程内回退
- 数据库迁移、种子数据、备份和恢复
- 健康检查、Prometheus 指标和 OpenTelemetry 追踪
- Docker Compose 部署

## 验收标准

一个版本只有在以下条件均满足时才可标记为完成：

1. `make check` 通过。
2. 新功能包含相应测试，修复包含回归测试。
3. 数据库变更可迁移；涉及恢复流程时完成恢复验证。
4. REST 变更已同步 OpenAPI 文件。
5. 配置、部署或用户行为变更已同步 README 或 SOP。
6. 未完成能力在[项目状态](./STATUS.md)中明确记录，不以规划项冒充已交付能力。

## 后续方向

后续产品方向包括多租户与配额、API 用量计量、计费、SSO/OIDC、媒体处理、完整 GraphQL、外部插件机制和 SDK。具体顺序及退出条件见[路线图](./ROADMAP.md)。
