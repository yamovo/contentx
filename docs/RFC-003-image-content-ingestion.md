# RFC-003：图片/截图内容摄取契约

| 项目 | 内容 |
|---|---|
| 状态 | 草案：边界与契约已定义，尚未实施，不构成版本承诺 |
| 日期 | 2026-09-24 |
| 目标 | 让用户把图片/截图通过视觉摄取管线转为带字段出处的草稿内容，复用现有草稿治理与 Agent 黄金路径，不产生任何自动发布 |

## 1. 问题

内容经常被困在图片里：聊天截图、回执、名单、单据、幻灯片、文档照片。当前 ContentX 只能通过 REST/MCP 接收结构化内容，用户只能手工转录这些图片。

简单的“图片→文字”不满足 Headless CMS 的要求：抽取结果必须映射到具体 ContentType 的字段，必须给出字段级置信度与可回溯出处，并且必须进入受治理的草稿—发布流程。

本能力还受到以下边界约束：

- 不得绕过草稿/发布权限与独立发布授权（RFC-002 与 Agent 黄金路径）。
- 外发必须遵守 `AI_ALLOW_OUTBOUND` 与既有 provider 抽象，不得内置任何凭据。
- 图片可能含敏感个人信息，需明确保留期与删除策略。
- 多租户隔离、审计 envelope、限流与既有 AI 端点采用同一套标准。

## 2. 摄取管线

全部步骤为确定性编排 + 可替换 provider，不允许“尽力填充”：

1. **接入与质量门禁**：校验格式、大小、分辨率与模糊程度；不合规图片以 4xx 拒绝。
2. **视觉抽取**：OCR 或视觉语言模型按目标 ContentType 派生的**严格 JSON schema** 输出字段候选；输出不符合 schema 一律拒绝，不产生半成品。
3. **字段级置信与出处账本**：每个字段记录来源图片、区域框（bounding box）、provider/模型与分数；原图存入媒体库并与候选条目关联。
4. **候选落为草稿**：输出为 `status=draft` 的 ContentEntry（或摄取候选暂存区），低置信字段显式标注；**永不自动发布**。
5. **复核与发布**：复核界面按字段高亮原图区域；发布仍走现有审批/独立发布授权与审计；批量摄取支持近似图片去重与相同文档键合并。

## 3. 接口与配置（计划）

```http
POST /api/v1/ingest/vision
# multipart：图片（可多张）+ 目标 content type uid + locale
# → 返回草稿 document_id、字段置信度、缺失/低置信字段与原图 media id
```

- MCP 提供 `ingest_vision` 写工具，遵循 `提议 → 确定性校验与 diff → 审批 → 独立发布授权` 路径。
- `VISION_INGEST_ENABLED=false` 为默认值；复用 `AI_ALLOW_OUTBOUND` 与既有 AI provider 配置；提供本地 dummy vision provider 供离线 CI。
- 租户范围、权限、限流与审计与 `/ai/*` 端点同标准。

## 4. 安全与治理边界

- 默认关闭；未配置 provider 或禁止外发时只有 dummy provider 可用，外部调用被拒绝。
- 摄取结果只能创建草稿；任何携带 `status=published` 的摄取请求一律拒绝。
- 权限复用内容 create 权限并增加独立 `ai.ingest` 权限位；MCP 主体每次调用再验证并绑定会话。
- 摄取、抽取、复核与发布各环节写统一审计 envelope，并关联原图 media id。
- 图片按敏感数据处理：提供保留期与删除入口，不进入日志正文，不用于训练。
- 资源边界：单图大小、批量数量、像素上限与 provider 成本上限均为硬约束。

## 5. 实施顺序

1. RFC 评审固定边界（本草案）。
2. dummy vision provider、严格 schema 校验与字段出处数据结构，CI 全程离线。
3. REST 摄取端点落草稿，补权限拒绝回归并同步 OpenAPI。
4. MCP `ingest_vision` 工具、审计与独立限流。
5. 复核界面字段高亮与原图联动；批量去重。
6. 真实 provider 端到端验证（依赖 API key，与 ROADMAP §3.3 第 6 项同口径）。

## 6. 最小测试矩阵

- 默认关闭时端点不可用；开启但外发禁止时仅 dummy provider 可用，外部调用被拒。
- 抽取结果不符合 schema → 4xx，不产生草稿或媒体孤儿。
- 摄取只能建草稿；携带 published 状态被拒绝。
- 每个字段可回溯到图片与区域框；删除原图后的出处处理有明确定义。
- tenant A/B 的图片与草稿不串读；MCP 与 REST 权限矩阵一致。
- 超限单图/超限批量被拒；审计可按关联字段串起全链路。
- OpenAPI 零漂移。

## 7. 暂不包含

- 端到端“截图即发布”（明确不做）。
- 内置或捆绑视觉模型凭据、模型微调。
- 视频与 PDF 摄取（PDF 另走文档摄取路线）。
- 版面模板的自动学习。
- 图片的公共 CDN 交付策略。

## 8. 来源

本 RFC 的管线设计（质量门禁、版面聚类、字段绑定、证据账本与校正迭代）提炼自 [yamovo/roster-lens](https://github.com/yamovo/roster-lens) 的工程实践；该项目已于 2026-09-24 功能冻结，通用化在 ContentX 内继续。
