# 路线图

本文档记录 ContentX 的后续里程碑，不重复维护版本状态或详细操作步骤。当前事实以[项目状态](./STATUS.md)为准，验收方法见[标准操作流程](./SOP.md)。

## 规划原则

- 安全、数据正确性和可恢复性优先
- 每个里程碑必须有可验证的退出条件
- 未完成项目不得写入已交付功能
- 依赖外部服务的能力必须使用真实集成验证
- 完成一个里程碑后更新状态和变更日志

## 已完成

| 里程碑 | 结果 |
|---|---|
| 基础 CMS | 内容、用户、权限、管理后台和三种数据库支持 |
| 工程化 | 分层架构、缓存、迁移、测试和 CI |
| 生产基础 | Docker Compose、监控、备份恢复和发布流程 |
| 稳定性整改 | 安全加固、缓存保护、GraphQL 限制和测试补齐 |
| MCP 基础 | stdio、HTTP、资源、提示词及受控写入工具 |

历史版本的具体变更见[变更日志](../CHANGELOG.md)。

## 当前里程碑：安全与稳定性收口

### 范围

- Webhook 持久化队列、并发限制和退避抖动
- S3 驱动迁移到经过真实服务验证的 SDK
- 统一核对未提交安全整改及其回归测试
- 完成发布前文档、迁移和恢复验证

### 退出条件

- `make check` 通过
- 安全相关测试覆盖成功、拒绝和降级路径
- PostgreSQL 备份与恢复演练通过
- S3 使用真实兼容服务完成上传、读取和删除验证
- [项目状态](./STATUS.md)与[变更日志](../CHANGELOG.md)同步

## 下一里程碑：多租户基础

按以下依赖顺序推进：

1. 定义租户数据模型和迁移策略。
2. 在 Repository 层统一注入租户范围。
3. 补充跨租户读写隔离测试。
4. 增加租户管理、停用和配额。
5. 增加按租户与接口维度的用量计量。

退出条件是所有租户数据路径均有隔离测试，后台任务、缓存、搜索、Webhook 和 MCP 不得绕过租户边界。

## 状态定义

| 状态 | 含义 |
|---|---|
| 计划中 | 已定义目标，尚未开始实现 |
| 进行中 | 已有实现，但退出条件尚未全部通过 |
| 已完成 | 退出条件已验证，文档和变更日志已同步 |
| 延后 | 当前里程碑不再承诺，需重新排期 |
