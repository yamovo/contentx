## P0 — 发布阻断 / 安全 / 数据正确性

### P0-1 文章并发更新丢失（无乐观锁）★ 新发现 ✅ 已完成
**问题**：`ArticleService.Update` 采用 `FindByID → buildUpdateMap → repo.Update` 流程，整个过程没有乐观锁（无 version 列比较、无 `updated_at` WHERE 子句、无 `SELECT FOR UPDATE`）。两个编辑器同时保存同一篇文章时，后保存的会静默覆盖前者的修改，造成 **lost update**。

**证据**：
- [internal/models/models.go#L13-L18](file:///d:/Obsidian/03_Projects/contentx-main/internal/models/models.go) `BaseModel` 只有 `CreatedAt/UpdatedAt/DeletedAt`，无 `Version` 字段
- [internal/repository/article.go#L257-L308](file:///d:/Obsidian/03_Projects/contentx-main/internal/repository/article.go) `Update` 直接 `tx.Model(article).Updates(updates)`，无 `WHERE updated_at = ?` 条件
- [internal/services/article_service.go#L608-L642](file:///d:/Obsidian/03_Projects/contentx-main/internal/services/article_service.go) `Update` 无冲突检测

**影响**：多人协作场景下的数据丢失，修订历史只能记录最终状态无法还原中间修改。同类项目（Strapi、Directus、Payload）均通过乐观锁或 `updated_at` 比较防御此问题。

**建议**：在 `UpdateArticleRequest` 增加 `expected_updated_at` 字段，`repo.Update` 的 WHERE 子句加上 `updated_at = ?`，受影响行数为 0 时返回 `409 Conflict`；或引入 `Version` 列做乐观锁。

**完成**：文章新增 `version` 乐观锁字段和生产迁移 007；REST 与 MCP 更新入口强制携带 `expected_version`，Repository 使用原子 `WHERE version = ?` 更新并递增版本，冲突返回 `409 CONCURRENT_MODIFICATION`。管理后台会保留本地内容并提示重新加载，迁移、Repository、Service、Handler、MCP 和前端交互均有回归测试。

### P0-2 审计日志严重不完整 ★ 新发现 ✅ 已完成
**问题**：`ActivityLogger` 中间件只记录 HTTP 方法、路由模板、IP、UserAgent、UserID，**不记录 `EntityID`（永远为 0）、不记录操作细节（`Details` 永远为空）、不记录失败操作（status >= 400 跳过）、不记录登录失败/锁定/权限拒绝**。无法回答"谁在何时改了哪篇文章/哪个角色/哪个配置"这一基本审计问题。

**证据**：
- [internal/middleware/middleware.go#L177-L210](file:///d:/Obsidian/03_Projects/contentx-main/internal/middleware/middleware.go) `ActivityLogger` 仅写入 `{UserID, Action: method, Entity: c.FullPath(), IP, UserAgent}`，`EntityID` 和 `Details` 字段从不填充
- [internal/models/models.go#L423-L435](file:///d:/Obsidian/03_Projects/contentx-main/internal/models/models.go) `ActivityLog` 模型有 `EntityID` 和 `Details` 字段但未被使用
- 登录失败、账户锁定、权限拒绝、4xx 写操作均不记录（`status >= 400` 直接 return）

**影响**：安全事件无法追溯；合规审计不达标；同类项目（Strapi/Directus）均在业务层记录实体级审计（含 before/after 摘要），ContentX 当前只有"某人调用了某路由"级别的日志。

**建议**：在 service 层关键操作（文章发布/状态变更、角色/权限变更、用户启停、系统配置变更、备份恢复、Webhook 增删）补充业务级审计，写入 `EntityID` 和 `Details`（JSON 摘要，敏感字段脱敏）；登录失败/锁定也需记录。

**完成**：统一业务审计器已覆盖文章创建、更新及生命周期操作，用户创建、角色/状态变更、删除和密码重置，角色权限变更，系统配置，Webhook 增删，以及备份创建、恢复和删除；认证失败、TOTP 缺失、账户锁定、失败写操作与 401/403 权限拒绝均会留痕。记录包含可用的 Actor、EntityID、JSON 摘要、IP 和 UserAgent；审计器对密码、密钥、Token 等嵌套字段统一递归脱敏，Webhook URL 额外移除用户信息、查询参数和片段。审计写入失败仅告警，不阻断主业务。

### P0-3 S3 存储驱动仍为简化实现 ✅ 已完成
**问题**：S3 驱动使用自封装签名而非官方 SDK，未经过真实兼容服务（MinIO/R2/AWS）的端到端验证，存在签名规范偏差、大文件分片、错误码处理等盲点。

**证据**：[internal/storage/s3.go](file:///d:/Obsidian/03_Projects/contentx-main/internal/storage/s3.go) 自实现 HTTP 签名；[ROADMAP.md](../ROADMAP.md) 当前里程碑退出条件明确要求"S3 使用真实兼容服务完成上传、读取和删除验证"。

**影响**：生产部署到 S3/MinIO/R2 时可能出现签名失败、上传中断、删除不幂等等问题，且难以排查。

**建议**：迁移到 `aws-sdk-go-v2`（或 MinIO Go Client），用 testcontainers + MinIO 跑真实集成测试覆盖上传/读取/删除/分片/错误码。

**完成**：S3 驱动已迁移到 `minio-go/v7`，由 SDK 负责 AWS Signature V4、流式分片上传、重试和错误响应；媒体服务上传、数据库失败回滚、单删和批删均已接入统一 `storage.Driver`。2026-07-29 使用校验过 SHA-256 的官方 MinIO `RELEASE.2025-09-07T16-13-09Z` 在 Windows 本地真实服务完成端到端验证，覆盖上传后 SDK 读取、删除后不存在、幂等删除、预签名 URL 实际下载、bucket 创建、17 MiB 分片上传和错误凭据拒绝。MinIO 已实测；R2/AWS 仍需部署方用自身账户做上线前冒烟验证。

### P0-4 统一回归验证 ✅ 已完成

## P1 — 高 ROI 改进

### P1-1 密码策略前后端不一致 ★ 新发现 ✅ 已完成
**问题**：后端 `auth.ValidatePasswordStrength` 要求 8+ 字符且含大小写+数字，但前端 `RegisterView.vue` 的表单规则是 `min: 6`，无复杂度要求。用户输入 6-7 位密码时前端通过、后端拒绝，UX 割裂。`ProfileView.vue` 的密码修改规则同样是 `min: 8` 但无复杂度提示。

**证据**：
- [internal/auth/password.go#L18-L82](file:///d:/Obsidian/03_Projects/contentx-main/internal/auth/password.go) `MinPasswordLength = 8` + 大小写+数字校验
- [web/src/views/login/RegisterView.vue#L131-L135](file:///d:/Obsidian/03_Projects/contentx-main/web/src/views/login/RegisterView.vue) `password: [{ min: 6, message: '密码至少6个字符' }]`
- 无常见弱密码黑名单（如 `password123`、`qwerty123`）

**建议**：前端规则与后端对齐（`min: 8` + 复杂度提示），复用同一份校验逻辑（前端可引入 zxcvbn 做强度评分）。

### P1-2 批量操作无上限 ★ 新发现 ✅ 已完成
**问题**：`BulkAction`、`BulkPublish`、`BulkDelete`、`BulkUpdateStatus`、`BulkMoveCategory`、`BulkSetPinned` 等批量端点没有对 `article_ids` 数量做上限校验，传入超大数组（如 10000 个 ID）会直接落到数据库，可能造成锁表或长事务。

**证据**：
- [internal/handlers/article.go#L237-L255](file:///d:/Obsidian/03_Projects/contentx-main/internal/handlers/article.go) `BulkAction` 直接 `h.svc.BulkAction(req)`，无 `len(req.ArticleIDs)` 校验
- [internal/repository/article.go#L61-L66](file:///d:/Obsidian/03_Projects/contentx-main/internal/repository/article.go) `BulkPublish(articleIDs []uint, ...)` 等接口无上限约束
- [internal/config/config.go#L344](file:///d:/Obsidian/03_Projects/contentx-main/internal/config/config.go) `LimitsConfig` 有 `MaxPageSize: 100` 但无 `MaxBulkActionSize`

**建议**：在 `LimitsConfig` 增加 `MaxBulkActionSize`（建议 100），handler 层校验 `len(articleIDs) > MaxBulkActionSize → 400`。

### P1-3 测试覆盖率回补
**问题**：整体行覆盖率 37.3%，函数覆盖率 38.8%，仅略高于 35% 阈值；阈值已从 42%/85% 下调到 35%/70%。`features/` 下 11 个子模块完全零覆盖，覆盖率趋势向下。

**证据**：
- 11 个零覆盖模块：`features/backups/`、`features/menus/`、`features/plugins/`、`features/roles/`、`features/seo/`、`features/settings/`、`features/system/`、`features/themes/`、`features/tokens/`、`features/users/`、`features/webhooks/`
- 核心模块覆盖率优秀（API 86%、auth 100%、articles 98%），整体被未测试模块拖低

**建议**：优先补 `features/users/`、`features/roles/`、`features/webhooks/` 三个高频调用模块的 composables 测试，恢复 42% 门槛。

### P1-4 测试执行时间长
**问题**：Handler + Service 测试需要 5 分钟+ 才能完成，影响迭代效率。

**证据**：[internal/services/](file:///d:/Obsidian/03_Projects/contentx-main/internal/services) 与 [internal/handlers/](file:///d:/Obsidian/03_Projects/contentx-main/internal/handlers) 全量测试 67s + 24s（本地），CI 上更长。

**建议**：审查测试 setupTestDB 是否每个用例都重建表/库，能否复用 schema；mock 仓库的测试应明显快于真实 DB 测试。

### P1-5 敏感端点账户维度限流 ✅ 已完成
**问题**：已有分组限流（auth 10/min、upload 20/min、comment 30/min，均为 IP 维度），但注册、密码重置、TOTP 验证等敏感端点没有账户/邮箱维度的限流，攻击者可绕过 IP 限流对特定账户撞库。

**证据**：
- [internal/handlers/routes.go#L132-L146](file:///d:/Obsidian/03_Projects/contentx-main/internal/handlers/routes.go) `auth` 组限流 10/min/IP
- [internal/auth/login_guard.go](file:///d:/Obsidian/03_Projects/contentx-main/internal/auth/login_guard.go) LoginGuard 有账户维度锁定，但注册、密码重置、TOTP 验证无账户维度限流

**建议**：注册端点按 IP + 邮箱维度限流；密码重置按邮箱维度限流。

## P2 — 架构一致性 / 体验

### P2-1 E2E 测试覆盖不足
**问题**：Playwright E2E 仅覆盖认证流程、文章 CRUD、权限矩阵，缺少 7 个关键场景。

**待补场景**：
1. 媒体上传、选择、删除
2. 动态内容条目的主要成功与失败路径
3. 备份和 Webhook 的主要成功与失败路径
4. 角色权限影响菜单、路由和操作按钮的完整验证
5. Editor 审核、发布、定时、归档及跨作者编辑
6. Author 创建草稿、编辑本人内容并提交审核，但不能发布
7. 文章和页面 CRUD，且页面类型不会被改写

### P2-2 ProfileView TOTP 迁移不完整
**问题**：ProfileView 已迁移到 Vue Query（`useProfileQuery` + `useProfileMutation`），但 TOTP 相关操作（`totpApi.status/setup/enable/disable`）仍使用手动 API 调用，未完全统一。

**证据**：[web/src/views/settings/ProfileView.vue#L380-L448](file:///d:/Obsidian/03_Projects/contentx-main/web/src/views/settings/ProfileView.vue) `fetchTotpStatus`/`startTotpSetup`/`confirmTotpEnable` 为手动 axios 调用。

### P2-3 部分路由未指向 pages/ 薄壳
**问题**：以下路由仍直接指向 `@/views/` 而非 `pages/` 薄壳：
- `ContentTypeList` → `views/content/ContentTypeList.vue`
- `ContentEntryList` → `views/content/ContentEntryList.vue`
- `NotFound` → `views/shared/NotFound.vue`

（Login 保留直接引用是合理的；NotFound 和 Content 模块应补充 pages/ 薄壳）

### P2-4 评论列表不支持 URL 参数预筛选
**问题**：仪表盘"待审评论"卡片跳转到 `/admin/comments` 后无法直达待审状态，需手动切换筛选。

**建议**：支持 `?status=pending` 类参数，列表组件读取 query 初始化筛选。

### P2-5 设计系统采用率低
**问题**：`web/src/shared/ui/` 有 10 个设计系统组件（AppShell、AsyncState、ConfirmAction、DataTablePage、EmptyState、FilterBar、FormSection、PageHeader、PermissionGate、StatusBadge），但仅在 3 个视图中实际采用（CategoryList、TagList、ArticleList）。其余 17+ 个视图仍直接拼装 Element Plus 组件，异步状态展示不统一。

### P2-6 Swagger 注释维护
**问题**：计划要求所有已挂载路由补齐 Swagger 注释并重新生成 `docs/api`，生成结果必须和仓库零差异。当前 Swagger 注释覆盖率 95.6%（109/114 方法），尚未验证零差异。

### P2-7 可观测性端到端验证
**问题**：Prometheus metrics、OpenTelemetry tracing 中间件已集成但缺乏端到端验证，无法确认指标和追踪数据实际正确上报。

## P3 — 不阻断发布，排期消化

### P3-1 Sass Legacy API 弃用警告
构建时出现 28 个 Dart Sass 弃用警告：legacy JS API 将在 Dart Sass 2.0.0 移除。需要升级 Sass 配置。

### P3-2 DashboardCharts chunk 偏大
`DashboardCharts` chunk 为 515KB minified（175KB gzip），低于 200KB gzip 门禁但 minified 体积超 500KB。ECharts 按需引入还有优化空间。

### P3-3 无障碍审计未执行
计划要求满足 WCAG 2.2 AA、axe 扫描无 Critical/Serious 问题、`prefers-reduced-motion` 支持、浅色/暗色截图回归，均未执行。

### P3-4 种子密码与 .env 不同步
`seedAdminUser` 仅在用户表为空时写入 `ADMIN_PASSWORD`，后续修改 `.env` 不会更新存量账号。建议提供密码重置子命令或在文档中明确说明。

### P3-5 国际化能力缺失
项目无 i18n 框架，全站文案硬编码中文。完整中英切换需引入 vue-i18n 并抽取 40+ 文件文案，已评估为低 ROI，暂不排期，有英文用户需求时再启动。（[PRD.md](../PRD.md) 已列为非目标）
